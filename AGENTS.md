# Repository guidance

For API endpoint, response-shape, or football data provider work, read and follow [`skills.md`](skills.md). For provider identity, canonical entities, and duplicate prevention, also follow [`docs/data-source-mapping.md`](docs/data-source-mapping.md).

Document important implementation work in the same change. Update the most relevant repository Markdown file (for example, `README.md`, an endpoint/provider reference, or an operational guide) with durable behavior, decisions, configuration, limitations, and migration or rollout steps. For substantial work, add a focused doc if no existing file is appropriate. Do not leave important implementation details only in code comments, chat, or commit messages. Follow [`skills.md`](skills.md) for the documentation checklist.
